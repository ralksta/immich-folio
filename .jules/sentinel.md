## 2024-08-11 - Unconstrained Base64URL Decoding DoS
**Vulnerability:** The decodeAssetId function in lib/tokens.ts accepted arbitrary length tokens and passed them directly to Buffer.from(..., 'base64url'), creating a risk of massive memory allocation (memory exhaustion/CPU DoS).
**Learning:** Functions that decode tokens from URLs (like GET /api/image/:token) must limit the input string length before passing it to Buffer.from. Otherwise, a maliciously crafted huge token can cause the Node.js process to throw RangeError (Invalid string length) or exhaust memory, despite being wrapped in a try/catch.
**Prevention:** Always enforce a strict maximum length check on opaque URL tokens before decoding them.
## 2024-05-24 - Unhandled Exception DoS in Webhook Signature Verification
**Vulnerability:** The webhook endpoint passed user-controlled input directly to `crypto.timingSafeEqual` without verifying buffer length. If the input signature length differed from the expected hash length, `timingSafeEqual` would throw a `RangeError`, which could lead to Unhandled Exception Denial of Service (DoS) if not caught correctly. Additionally, unbounded input passed directly to `Buffer.from` causes memory exhaustion DoS.
**Learning:** `crypto.timingSafeEqual` strictly requires buffers of the exact same byte length. Unconstrained variable-length inputs can cause immediate memory exhaustion (DoS) if security functions allocate buffers matching the input length.
**Prevention:** Always verify input buffer lengths or hash to a fixed length before comparison using `timingSafeEqual` and enforce maximum string length check on inputs before processing.
