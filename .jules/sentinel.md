## 2024-05-18 - Fix DoS vector in crypto.timingSafeEqual
**Vulnerability:** The application was vulnerable to memory exhaustion DoS when comparing passwords, because `Buffer.alloc` was fed an unchecked input length. Additionally, `crypto.timingSafeEqual` was directly passed user input lengths, leading to crashes ("Input buffers must have the same byte length") due to unhandled exceptions when inputs differed in length.
**Learning:** In Node.js, `crypto.timingSafeEqual` strictly demands exact byte length matches. Supplying variable length input crashes the server, and allocating memory proportional to unconstrained input enables memory exhaustion (DoS).
**Prevention:** Always enforce a strict maximum length limit on input strings early. Hash variable-length secrets (like passwords or tokens) to a fixed length (e.g., HMAC-SHA256) before using `timingSafeEqual`. This prevents both side-channel timing attacks leaking length, DoS attacks via huge allocations, and server crashes from length mismatches.
